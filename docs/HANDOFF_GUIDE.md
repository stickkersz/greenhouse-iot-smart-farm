# คู่มือส่งต่อระบบ — สำหรับเจ้าของ/ผู้ดูแลคนถัดไป

เอกสารนี้เขียนขึ้นเพื่อให้ **บริษัท ปุ๋ยไวกิ้ง จำกัด** ดูแล/แก้ไข/อัปเกรดระบบ Greenhouse IoT Smart Farm
ต่อได้เอง โดยไม่ต้องรอ Tonkla (IT Intern ผู้พัฒนาเดิม) — ไม่ว่าจะเป็นเจ้าของกิจการเข้ามาดูเอง หรือจ้าง
โปรแกรมเมอร์/ช่างใหม่มารับช่วงต่อ

**อ่านเอกสารนี้ก่อนเป็นอันดับแรก** — มันจะชี้ไปยังเอกสารอื่นในโฟลเดอร์เดียวกันตามสถานการณ์ ไม่ต้อง
อ่านทุกไฟล์ตั้งแต่ต้น

## 2. สิทธิ์เข้าถึงที่ต้องขอจาก Tonkla ก่อนวันสุดท้าย

ระบบนี้ผูกอยู่กับ 2 บัญชีหลักที่ปัจจุบันเป็นของ Tonkla — **ถ้าไม่โอน/ไม่เพิ่มสิทธิ์ก่อน จะเข้าถึงระบบไม่ได้เลย**
แม้จะมีโค้ดในเครื่องครบก็ตาม:

| บัญชี | ใช้ทำอะไร | ต้องขอสิทธิ์อะไร |
|---|---|---|
| **GitHub** — `github.com/stickkersz/greenhouse-iot-smart-farm` | เก็บโค้ดทั้งหมด + ประวัติการแก้ไข | ขอเป็น **Collaborator** (หรือ transfer ownership ถ้า Tonkla จะไม่ยุ่งกับ repo อีกแล้ว) — ทำที่ Settings → Collaborators ของ repo |
| **Firebase Console** — โปรเจกต์ `greenhouse-iot-smart-farm` | ฐานข้อมูลจริง (Realtime Database) + hosting เว็บ dashboard + จัดการ account พนักงาน | ขอเป็น **Owner หรือ Editor** ที่ [console.firebase.google.com](https://console.firebase.google.com) → โปรเจกต์ → ⚙️ Project settings → Users and permissions |

**ถ้าไม่มีใครรับช่วง Firebase ต่อ** ให้อย่างน้อยเปลี่ยนอีเมลกู้คืนบัญชี Firebase ให้เป็นอีเมลบริษัท
ไม่ใช่อีเมลส่วนตัวของ Tonkla — ไม่งั้นถ้าติดต่อ Tonkla ไม่ได้ในอนาคต ระบบทั้งหมดกู้คืนไม่ได้

**URL ที่ต้องรู้จักไว้:**
- Dashboard ที่ใช้งานจริง: `https://greenhouse-iot-smart-farm.web.app`
- โค้ดทั้งหมด: `https://github.com/stickkersz/greenhouse-iot-smart-farm`

## 3. ถ้าจะจ้างโปรแกรมเมอร์ใหม่มาทำต่อ — ให้เขาเริ่มตรงนี้

ส่งลิงก์ repo ให้เขา แล้วบอกให้อ่านตามลำดับนี้ (ประมาณ 30-45 นาที อ่านครบ):

1. `README.md` (root ของ repo) — ภาพรวมระบบ, hardware, วิธี setup/compile/deploy, checklist ก่อน deploy
2. `docs/PROJECT_MEMORY.md` — **สำคัญที่สุด** เก็บประวัติบั๊กที่เจอจริงและวิธีแก้ พร้อมเหตุผลว่าทำไม
   ถึงเลือกแก้แบบนี้ไม่ใช่แบบอื่น มีหลายจุดที่ "ดูเหมือนน่าจะแก้แบบง่ายกว่านี้ได้" แต่จริงๆ เคยลองมาแล้ว
   ไม่ได้ผล — อ่านก่อนแก้อะไรกันเสียเวลาแก้ปัญหาเดิมซ้ำ
3. `docs/Firebase_Database_Structure.md` — ก่อนแตะ dashboard หรือ Firebase rules
4. `docs/pinout_v2.md` — ก่อนแตะฮาร์ดแวร์/สายไฟ

จากนั้นให้ทำตาม **Setup — firmware** และ **Setup — Firebase & dashboard** ใน `README.md` เพื่อตั้ง
เครื่องมือในเครื่องตัวเอง (ต้องมี `smartfarm_firmware/config.h` ที่ไม่ได้อยู่ใน repo — ต้องสร้างเองจาก
`config.h.example` แล้วใส่ WiFi/Firebase key จริง)

## 4. กฎเหล็ก — ห้ามพลาดไม่ว่าใครจะมาทำต่อ

1. **รัน `npm test` ให้ผ่านทั้งหมดก่อน deploy หรือ flash ทุกครั้ง** — ไม่มีขั้นตอน build ที่ซับซ้อน
   แต่การข้ามเทสมีประวัติทำให้ของพังจริงมาแล้ว
2. **ห้าม commit ไฟล์ `smartfarm_firmware/config.h`** — มี WiFi password และ Firebase key อยู่ข้างใน
   ไฟล์นี้ถูก gitignore ไว้แล้ว อย่าไปแก้ `.gitignore` เพื่อบังคับ commit มันเด็ดขาด
3. **ห้ามใช้ Relay ที่ GPIO12** — เป็น strapping pin ทำให้บอร์ด boot ไม่ขึ้น (เคยเจอมาแล้ว ย้ายไป
   GPIO25 แทน)
4. **แก้ค่า `VENT_HYST` ต้องแก้ 3 จุดพร้อมกัน** (`auto_control_logic.h`, dashboard, `database.rules.json`)
   — มี `npm run test:sync` เช็คให้อัตโนมัติ ถ้าเทสนี้แดงคือมีจุดใดจุดหนึ่งลืมแก้
5. **หลัง flash หรือ deploy เสร็จ ต้องทดสอบบนบอร์ดจริงเสมอ** — เทสในเครื่อง (`npm test`) ผ่านไม่ได้
   แปลว่าใช้งานได้จริงบนฮาร์ดแวร์ 100% (โดยเฉพาะเซนเซอร์ SHT35 จริง)
6. **เลขเวอร์ชัน firmware อยู่ 6 ที่ในโค้ด ต้องขยับพร้อมกันทุกครั้ง** — มี checklist อยู่ที่หัวไฟล์
   `smartfarm_firmware/smartfarm_firmware.ino` เพื่อกันเวอร์ชันไม่ตรงกันระหว่าง Serial/LCD/dashboard

## 5. ผังตัดสินใจเมื่อมีปัญหาและ Tonkla ติดต่อไม่ได้

```
มีปัญหา
├─ ใช้งานทั่วไป (ปั๊ม/พัดลมไม่ทำงาน, dashboard ขึ้นออฟไลน์, เพิ่มคนใหม่)
│   └─ ดู docs/DAILY_OPERATIONS_CHECKLIST.md ก่อน — ครอบคลุมเคสที่เจอบ่อยและวิธีแก้เบื้องต้น
│       (ส่วนใหญ่แก้ได้ด้วยการปิด-เปิดไฟตู้คอนโทรล ปลอดภัย 100%)
│
├─ อยากเปลี่ยน threshold (อุณหภูมิ/ความชื้นที่ให้ปั๊ม/พัดลมทำงาน)
│   └─ ทำได้จาก dashboard เองเลย ไม่ต้องแก้โค้ด — มี preset ตามฤดูให้เลือกด้วย
│
├─ อยากแก้/เพิ่มฟีเจอร์ในโค้ด หรือเปลี่ยนฮาร์ดแวร์
│   └─ ต้องมีคนที่เขียนโค้ดได้ (จ้างใหม่หรือทำเอง) → เริ่มจากข้อ 3 ด้านบน
│       อ่าน PROJECT_MEMORY.md ก่อนเสมอ กันแก้ปัญหาเดิมซ้ำที่เคยพิสูจน์แล้วว่าไม่ได้ผล
│
├─ กลิ่นไหม้ / เสียงผิดปกติ / ไฟฟ้าลัดวงจร
│   └─ ตัดไฟเบรกเกอร์ทันที — นี่คือความปลอดภัยทางกายภาพ ไม่ใช่ปัญหาซอฟต์แวร์ อย่ารอถามใคร
│
└─ ระบบใช้งานไม่ได้เลยและไม่มีใครแก้โค้ดได้
    └─ ระบบ auto control (เซนเซอร์ + relay) ทำงานแบบ **offline-first** — ไม่ต้องพึ่ง WiFi/Firebase
       เลย ถ้า dashboard ใช้ไม่ได้ โรงเรือนยังคุมอุณหภูมิ/ความชื้นได้เองตามปกติ ไม่ใช่จุดที่ต้องรีบสุด
```
